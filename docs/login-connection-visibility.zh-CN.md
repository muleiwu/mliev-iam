# 登录方式展示配置

社交和企业身份连接均可设置全局展示，也可按应用独立选择。同一类型的多个连接分别配置，例如两个微信小程序可只在各自的应用登录页展示。

## 全局展示

在「身份连接」新建或编辑连接，设置「全局展示」。新建连接默认关闭；打开后，已启用且具备认证能力的连接会出现在继承全局设置的登录页。升级前已有连接保留全局展示状态，不会自动隐藏。

## 应用独立配置

在 OIDC 应用创建、编辑页面或应用详情的「登录方式展示」页签选择：

- **继承全局**：默认选项，跟随各连接的全局展示开关。
- **独立配置**：只展示该应用选中的连接，可选未全局展示的连接，也可排除全局展示的连接。全部不选表示隐藏所有社交和企业登录入口。

管理后台和个人中心内置应用同样支持设置，重启后保留。连接停用、删除或移除认证能力后，其入口自动隐藏；原有选择会标记为不可用，可保留或移除。排序沿用连接的排序设置。

### 两个小程序分别展示

1. 编辑两个微信小程序身份连接，关闭各自的「全局展示」，保持连接启用。
2. 打开应用 A 的「登录方式展示」，选择「独立配置」，勾选小程序 A 以及此应用需要的其他连接并保存。
3. 在应用 B 中同样选择小程序 B 及所需连接。
4. 分别从应用 A、B 发起登录，检查各自入口。继承全局的其他应用不会展示这两个小程序。

## 展示与认证的区别

此设置只控制网页登录入口，不是认证授权策略。直接认证链接、原生小程序登录和账号绑定继续按现有规则工作。原生小程序登录仍通过应用协议配置中的 `miniProgram` 设置；隐藏网页入口不会关闭它。个人中心绑定列表仍显示所有已启用且具备认证能力的连接。

## API

- 身份连接管理接口新增 `showGlobally: boolean`；创建时省略为 `false`，更新时省略保留原值。
- 应用管理接口新增顶层 `loginConnections: { "mode": "inherit" | "custom", "connectionIds": number[] }`。未配置的应用视为 `inherit`；更新时省略字段保留原值，恢复继承需明确提交 `mode: "inherit"`。`custom` 的空列表合法。新增选择必须对应有效连接，已有不可用选择允许保留。
- 登录列表使用 `GET /api/identity-connections?purpose=login&session_id=...`，应用由浏览器绑定的授权会话决定。未提供会话时返回全局展示列表；无效、过期或不属于当前浏览器的会话返回错误，不回退到全局列表。
- 无参数的 `GET /api/identity-connections` 保持原有全部已启用认证连接列表，用于账号绑定等已有调用。

MySQL、PostgreSQL 和 SQLite 均通过版本化迁移添加配置字段。已有连接回填为全局展示，新增连接默认关闭；已有应用继承全局。迁移再次运行不会覆盖已经保存的设置。
