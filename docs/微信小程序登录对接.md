# 微信小程序原生登录

每个业务小程序注册独立 IAM 公开客户端。小程序将 `wx.login()` 的临时 code 交给 IAM；IAM 验证微信身份、关联统一账号并签发当前应用的令牌。业务后端按应用校验 issuer、签名、audience、期限及权限，不使用 openid 作为内部主用户 ID。

## 1. 管理后台配置

1. 在「身份连接」创建类别为社交、类型为「微信小程序」的连接，填写 AppID、AppSecret 并启用。AppSecret 保存在加密认证凭据中，接口不回显。
2. 若需要跨小程序关联，填写 `openPlatformId`（开放平台归属标识）。只有实际绑定同一微信开放平台账号的小程序才能填写相同值；公司主体相同不代表开放平台归属相同。该标识由管理员维护，不是前端提交的可信声明。
3. 在 OIDC 应用创建或编辑页面启用「微信小程序登录」，选择连接及账号策略。客户端类型固定为公开客户端。勾选「仅用于小程序」后无需网页回调 URI，授权类型保留 `refresh_token`；同时支持网页授权时仍需配置合法回调和 PKCE。
4. 配置应用访问范围、scope 权限、注册必填字段和应用协议。在微信公众平台为小程序配置 IAM HTTPS `request` 合法域名，并开通手机号实时验证能力。

应用配置示例（通过现有应用管理 API 保存）：

```json
{
  "protocolType": "oidc",
  "protocolConfig": {
    "clientType": "public",
    "redirectUris": [],
    "responseTypes": [],
    "grantTypes": ["refresh_token"],
    "scopes": ["openid"],
    "miniProgram": {
      "enabled": true,
      "connectionId": 12,
      "accountPolicy": "auto_register"
    }
  }
}
```

微信连接的 AppID、AppSecret 通过 `credentials.authentication.clientId/clientSecret` 保存，归属标识放在 `config.openPlatformId`。存在过身份绑定后，AppID、归属和提供商类型不可修改；AppSecret 仍可轮换。未启用 `miniProgram` 的历史应用行为不变。

## 2. 登录 API

基础路径：`/api/auth/miniprogram/{client_id}`，其中 `client_id` 是 IAM 应用 UUID，不是微信 AppID。接口使用 JSON 和 IAM `{code: 0, message, data}` 响应包装，不使用浏览器 Cookie。

| 方法与路径 | 请求 | 作用 |
|---|---|---|
| `GET /config` | 无 | 应用名称、注册策略、注册字段、协议链接 |
| `POST /login` | `jsCode`, 可选 `scope`、`nonce` | 验证微信身份；scope 默认 `openid` |
| `POST /phone` | `phoneCode` | 验证手机号并关联账号或进入注册 |
| `POST /bind` | `username`, `password`, 可选 `captchaTicket` | 验证已有账号；复用 IAM 登录验证码策略 |
| `POST /complete` | `profile`, `acceptedAgreementKeys`, `approveScopes: true` | 补齐资料、同意协议及应用授权 |
| `POST /two-factor/send` | `method` | 发送短信/邮箱二次验证码 |
| `POST /two-factor/verify` | `method`, `code` | 完成二次验证并签发令牌 |

`/login` 之后，所有继续步骤使用 `Authorization: Bearer <transactionToken>`。事务最长 15 分钟，仅能用于创建它的应用及身份源。该 token 不是业务访问令牌；不要放入 URL、日志或持久化存储。事务只允许对应步骤推进，过期或已完成后重新调用 `wx.login()`。升级前缺少认证版本的未完成事务也会失效，客户端重新开始登录即可。

待完成响应示例：

```json
{
  "code": 0,
  "data": {
    "state": "phone_required",
    "transactionToken": "<opaque secret>",
    "expiresIn": 899,
    "scope": "openid"
  }
}
```

| state | 客户端下一步 |
|---|---|
| `phone_required` | 用户点击微信实时手机号授权按钮，提交独立 `phoneCode`；也可选择已有账号绑定 |
| `bind_required` | 输入已有 IAM 账号密码，调用 `/bind` |
| `profile_required` | 收集配置要求的邮箱/姓名/昵称，展示协议，调用 `/complete`；也可选择已有账号绑定 |
| `consent_required` | 展示应用身份、授权范围和协议，调用 `/complete` |
| `two_factor_required` | 根据 `twoFactorChallenge.methods` 展示可用方式，发送/验证第二因素 |
| `authenticated` | 保存 `tokens`，开始访问业务 |

`/complete` 示例：

```json
{
  "approveScopes": true,
  "acceptedAgreementKeys": ["global:terms", "global:privacy"],
  "profile": {
    "email": "user@example.com",
    "realName": "张三",
    "nickname": "小张"
  }
}
```

协议 key 必须以 `/config` 返回为准。用户名由服务端生成，新账号不创建密码；邮箱未经验证时不会标记为已验证。手机号只能从微信服务端取得，前端不能通过 profile 设置手机号或验证状态。已有关联账号的 profile 不会被这一步覆盖。

完成响应：

```json
{
  "code": 0,
  "data": {
    "state": "authenticated",
    "isNewUser": true,
    "tokens": {
      "access_token": "<JWT>",
      "refresh_token": "<opaque token>",
      "id_token": "<JWT>",
      "token_type": "Bearer",
      "expires_in": 3599,
      "scope": "openid"
    }
  }
}
```

`id_token` 仅在 scope 包含 `openid` 时返回。令牌包含统一账号的 `sub`、当前应用的 `aud`，issuer 为 `/oidc/{client_id}`。首次手机号、资料、协议、二次验证及应用准入检查全部通过前，不创建业务令牌、不写入最终身份绑定。

## 3. 账号关联规则

- 优先检查 `(AppID, openid)` 和 `(openPlatformId, unionid)`；归属未配置时不使用 UnionID 跨连接关联。历史绑定参与冲突检查，只有归属明确的映射才在成功登录时写入全局索引。
- `bind_existing`：未匹配的微信身份必须验证已有账号密码，不能注册或仅凭手机号关联。
- `auto_register`：未匹配身份必须授权手机号。仅当号码命中唯一、已验证、可登录的 IAM 用户时自动关联；未验证的号码转入显式账号绑定。停用用户、重复号码或微信标识冲突都不会自动合并。
- 无匹配账号时，完成注册字段和协议确认后创建账号并关联微信。没有应用准入权限时整个创建/绑定/签发事务回滚。
- 已关联账号不反复索取手机号。一个小程序取得的业务令牌不能用于其他客户端；账号互通不等于所有小程序共享一份会话。
- 已开启二次验证的账号必须完成验证。手机号自动匹配时，手机号作为第一因素，不能再次选手机号作为第二因素。原生端支持密码、TOTP、短信、邮箱、恢复码；Passkey 继续使用网页流程，无可用原生因素时拒绝签发。
- 未完成的原生事务会绑定用户认证配置版本。解绑、修改二次验证配置或管理员重置认证后，旧事务必须重新发起；微信已解绑时不能凭旧事务恢复绑定。
- 原生、遗留 code 登录和扫码登录共用跨连接冲突检查，登录查询不会提前补写新的 UnionID。既有账号首次获得合法 UnionID 时，在完成所需认证后补全标识；启用二次验证时延后到验证成功，失败或冲突时不写入。扫码确认和浏览器轮询会再次核对绑定。
- 冲突事件保存在 `we_chat_identity_conflicts`，不含微信密钥。管理员须核对账号归属后处理既有账号，不应直接改写索引来绕过冲突。

## 4. 手机号与微信凭证

示例使用 `button open-type="getRealtimePhoneNumber"` 和 `bindgetrealtimephonenumber`。用户同意后取得的 `code` 应作为 `phoneCode` 提交，与 `wx.login()` 的 `jsCode` 不可混用。

IAM 使用对应 AppID 的微信服务凭证调用 `wxa/business/getuserphonenumber`，同时提交已经通过 `code2Session` 验证的 openid，让微信校验手机号 code 与用户的绑定关系，并检查响应水印的 AppID 和时间。微信返回的手机号按国家区号规范化为 E.164。

微信手机号接口的响应不声明 code 来源是快速组件还是实时组件；因此示例固定使用实时组件，IAM 不信任客户端自报的“已实时验证”标志。实时能力及额度由小程序运营方在微信平台配置。

AppSecret、微信 access token、`session_key` 都留在服务端；`session_key` 不作为用户资料持久化，也不会返回业务端。此次迁移会删除历史 `raw_profile.session_key`。手机号采用新版 code 换号，不依赖 `encryptedData/iv` 解密。

## 5. 刷新、退出和错误处理

刷新使用 `POST /oidc/{client_id}/token`，表单编码提交 `grant_type=refresh_token`、`client_id`、`refresh_token`。公开客户端不提交 client_secret；刷新成功后原子替换本地 access/refresh token，多个并发调用共用一次刷新操作。

退出使用 `POST /oidc/{client_id}/revoke`，表单提交 `client_id`、`token=<refresh_token>`、`token_type_hint=refresh_token`。撤销成功后清理本地令牌；网络失败保留令牌以便重试。userinfo、JWKS 和现有会话管理沿用 OIDC 能力。

- HTTP 400：凭证、资料、身份冲突或授权校验失败。显示 message；微信 code 使用失败后重新获取，不盲目重试同一个 code。
- HTTP 401：事务过期、跨应用使用或已完成。清除事务，重新开始登录。
- HTTP 429：等待限流窗口后重试。
- 用户拒绝手机号授权：可再次授权，或显式绑定已有账号；不会创建半成品用户。
- 二次验证成功后若数据库提交失败，必须重新登录，不能复用已消费的验证码。

## 6. 运行示例和上线验证

示例目录：[`examples/wechat-miniprogram`](../examples/wechat-miniprogram)。在 `config.js` 填写公开的 IAM 域名和应用 UUID，在开发者工具导入项目并选择真实 AppID。它演示所有状态、协议阅读、实时手机号授权、令牌刷新和退出，不需要安装 npm 包。

自动化测试：

```sh
go test ./app/service ./app/controller ./app/service/protocol/... ./config/autoload ./migrations
go test -tags=integration ./migrations -run 'TestMigrationDialects/.*/(empty|miniprogram-upgrade)$' -count=1
node --test examples/wechat-miniprogram/utils/iam.test.cjs
cd admin-web
pnpm --filter @vben/web-antd typecheck
pnpm --filter @vben/web-antd build
```

真实联调需自行配置的测试应用、微信认证及手机号额度。按单应用登录、手机号拒绝/同意、已有账号绑定、二次验证、刷新与退出顺序验证，再用同一开放平台的第二个小程序核对相同 sub、不同 aud。功能默认关闭，迁移完成后逐个应用启用。

若 IAM 启用了图形验证码，业务小程序需接入该验证流程并向 `/bind` 提交 `captchaTicket`；最小示例不包含各验证码供应商的组件。不能为绕过验证而关闭服务端校验。

## 7. 现有网页和 PC 扫码流程

旧 `/social/*` 文档已废弃，当前网页/扫码接口均在 `/external-auth` 下：

- `POST /external-auth/:identifier/miniprogram/qrcode` 创建二维码，返回 `scanHandle`、仅浏览器持有的 `pollToken` 和二维码。
- `GET /external-auth/:identifier/miniprogram/qrcode/:scanHandle` 配合 `X-QR-Poll-Token` 轮询。
- `POST /external-auth/:identifier/miniprogram/qrcode/scan` 提交 `scanHandle`、`jsCode`，取得仅扫码设备持有的 `confirmToken`。
- `POST /external-auth/:identifier/miniprogram/qrcode/confirm` 提交 `scanHandle`、`confirmToken`、`action`。
- 网页后续绑定/注册使用 `/external-auth/bind-with-login`、`/external-auth/register` 及 HttpOnly continuation Cookie；并非旧的可公开传递 bindToken。

`/external-auth/:identifier/miniprogram/login` 保留兼容。它不是这里的应用范围原生接口，新小程序统一使用 `/api/auth/miniprogram/:client_id/*`。
