# 应用访问权限

在“应用详情 → 授权管理”中勾选“公开应用”并保存，所有已登录用户（包括后续新用户）都可以访问。原有用户、部门、角色范围会保留，取消公开后重新生效。未勾选公开且范围为空时，不允许任何用户访问。

公开设置只影响应用的人员访问范围；账号登录、应用启用状态、协议回调地址等检查继续生效。系统保护应用的范围仍由系统维护，不能设为公开。

## 接口与历史配置

授权范围读写接口增加 `isPublic` 字段，存储在现有 `applications.access_scope` JSON 内，无需新增数据库列。

| 保存的配置 | 访问规则 |
| --- | --- |
| `isPublic: true` | 所有已登录用户可访问，不受范围列表限制 |
| `isPublic: false` | 必须匹配用户、部门或角色之一；空范围拒绝所有用户 |
| 未提供 `isPublic` 的历史配置或旧接口请求 | 保持原行为：空范围公开，非空范围按列表授权 |

查询接口返回实际生效的布尔值，因此历史空范围应用在新页面中会显示为已勾选公开。

## 范围清除问题

人员详情按每页 20 人加载，但授权 ID 一次返回全部。旧页面仅把已加载的详情传给穿梭框；未加载或已删除的用户没有可见行，移除所有可见人员仍会残留隐藏 ID。角色被删除后也存在同类问题。只要残留 ID，后端仍把应用当作受限应用，新用户无法访问。

现在所有已选 ID 都有可见行，缺少详情时显示“用户 #ID”或“角色 #ID”，可以正常移除。公开标记独立于这些范围，因此勾选后不会受到历史残留范围影响。

回归测试覆盖 21 人只加载前 20 人后全部移除、已删除用户和角色、公开与受限模式切换、旧接口清空范围，以及 OIDC 登录入口。
