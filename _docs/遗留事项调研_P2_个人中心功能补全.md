# 遗留事项调研 · P2 — 个人中心功能补全

> 影响等级：**P2（功能补全，按需排期）**
> 调研日期：2026-07-15
> 前置：个人中心一期已上线（`frontend-oidc/src/views/account/AccountPage.vue` + `components/account/*`，后端 `/api/user/*` + `/social|identity/bind-auth`）。

三项补全功能：①邮箱/手机号修改+验证 ②社交账号用户设初始密码 ③个人中心独立登录入口。以下为现有基础设施与落地骨架。

## 0. 共性基础设施

### 0.1 个人中心鉴权（前提）
- `/api/user/*` 靠 **HttpOnly Cookie `user_access_token`** 鉴权，非 OIDC access_token。
- Cookie 名常量 `app/middleware/auth_middleware.go`（`UserCookieName`）；`AuthMiddleware` 取 token 顺序：`Bearer` 头 → `admin_access_token` → `user_access_token`；`GetCurrentUserID` 取当前用户。
- 签发/清除：`app/controller/user_session_cookie.go`，`issueUserSessionCookie(ctx, user, rememberMe)` **先于 OIDC Token 生成、与其解耦**（这是功能三可复用的关键）。
- 受保护用户组 `userAuth`（`config/autoload/router.go:234-240`，`Use(AuthMiddleware())`）。

### 0.2 验证码基础设施（功能一核心）
`app/service/verification_code_service.go`：
- `SendCode(ctx, receiver, type, sessionID, traceID)`：**60 秒频控**（`ratelimit:{type}:{receiver}`），验证码存 `verification:code:{type}:{receiver}:{sessionID}`，**TTL 5 分钟**，6 位 crypto/rand。
- `VerifyCode(...)`：Redis 比对，**一次性使用**（成功即 Del）。
- 类型枚举 `VerificationTypeEmail="email"` / `VerificationTypePhone="phone"`。
- 配置装配：`getVerificationCodeConfig()`（`oidc_auth_flow_controller.go:964`）从 `SettingService.GetPushSettings()` 读取。
- **sessionID 命名约定**用于隔离同一 receiver 的不同场景：登录 `login:{sessionID}:...`、注册 `register:{receiver}`、CompleteProfile 直接用 OIDC sessionID。**功能一建议新增** `change-email:{userID}` / `change-phone:{userID}`。
- captcha 校验：`captcha.NewManager(db).ValidateForScene(scene, ticket, ip, redis)`，场景含 `sendSms/sendEmail/login` 等。

### 0.3 User 模型 & 复用方法
`app/model/user.go`：`Email *string`/`Phone *string`（各带 `uniqueIndex` + DeletedAt 复合唯一）、`PasswordHash`（`json:"-"`）、`EmailVerifiedAt`/`PhoneVerifiedAt`（派生 `EmailVerified()`/`PhoneVerified()`）。
`app/dao/user_dao.go`：`ExistsEmail`/`ExistsPhone`（支持 excludeID）、`Update`/`UpdateById`。
手机号规范化：`utils.NormalizePhoneToE164(input, "CN")`。

## 功能一：邮箱/手机号修改 + 验证流程

### 现状
- 前端 `ProfilePanel.vue:97-99` 明确写死"邮箱与手机号需通过验证流程修改，暂不支持在此直接编辑"，只读展示 + 已验证/未验证 Badge。
- 自助更新 `UpdateMyProfile` **刻意排除**邮箱/手机（白名单 DTO `UpdateMyProfileRequest` 只含 nickname/realName/avatar/remark）。

### 可复用逻辑
- **完整"验证码→更新"范式**：`CompleteProfile`（`oidc_auth_flow_controller.go:1209`）已实现"提供邮箱→校验验证码→更新→置 verified→唯一冲突错误映射"，可直接照搬。
- **唯一性检查**：`ExistsEmail`/`ExistsPhone`。
- **置 verified**：`UserService.MarkContactVerified(userID, emailVerified, phoneVerified)`（`user_service.go:660`）——现成方法。

### 落地骨架
**后端 UserService 新增**：
```go
ChangeMyEmail(userID uint, newEmail, code string) error
ChangeMyPhone(userID uint, newPhone, code string) error  // 内部先 NormalizePhoneToE164
```
逻辑：规范化 → `ExistsEmail/ExistsPhone(newVal, userID)` 唯一性 → `VerifyCode(receiver=newVal, type, sessionID="change-{type}:{userID}", code)` → `UpdateById` 写新值 + `xxx_verified_at=now`（一步置 verified）。

**UserController 新增（`userAuth` 组，走 Cookie）**：
- `POST /api/user/send-contact-verification-code`：body `{ type, receiver, captchaTicket }`，sessionID 用 `change-{type}:{userID}`。**必须先校验新值未被占用再发码**。复用 `getVerificationCodeConfig`（建议提取为共享 helper）+ `ValidateForScene("sendEmail"/"sendSms")` + `SendCode`。
- `PUT /api/user/email`：`{ email, code }` → `ChangeMyEmail`。
- `PUT /api/user/phone`：`{ phone, code }` → `ChangeMyPhone`。

**DTO**：`ChangeMyEmailRequest{Email,Code}`、`ChangeMyPhoneRequest{Phone,Code}`、`SendContactCodeRequest{Type,Receiver,CaptchaTicket}`。

**前端**：`ProfilePanel.vue` 邮箱/手机行改为"修改"按钮 → 弹窗（新值 + 发码含 60s 倒计时 + 验证码输入）；`api/user.ts` 加 `sendContactCode/changeMyEmail/changeMyPhone`（`skipAuth: true`）。验证码 UI 可参考 RegisterFormPage/ProfileCompletionPage。

## 功能二：社交账号用户"设置初始密码"

### 现状与根因
- 无密码用户（`PasswordHash == ""`）走 `ChangePassword` 时，第一步旧密码校验 `verifyPassword(oldPwd, salt, "")` 必失败 → "旧密码错误"（`user_service.go:413-415`；passhash 包 `internal/pkg/passhash/passhash.go`）。
- 解绑"最后登录方式"保护：`PasswordHash == "" && accountCount <= 1` 时阻止（social `social_auth_service.go:373`，identity `identity_auth_service.go:213`，文案"这是您唯一的登录方式，无法解绑。请先设置密码或绑定其他账号"）。
- **前端拿不到"是否有密码"状态**：`UserResponse` / `ConvertToUserResponse` 不含 hasPassword（`PasswordHash` 为 `json:"-"`）；`SecurityPanel.vue` 硬编码"修改密码"表单，强制要求当前密码。

### 可复用逻辑
- 生成哈希：`UserService.GeneratePasswordHash`（`user_service.go:515`，argon2id）。
- 无旧密码写密码（参考）：`UserService.ResetPassword`（`user_service.go:452`，管理员用，直接 `UpdateById`）——逻辑几乎就是"设初始密码"，但缺"当前是否无密码"前置校验。

### 落地骨架
**后端 UserService 新增**：
```go
HasPassword(userID uint) (bool, error)          // user.PasswordHash != ""
SetInitialPassword(userID uint, newPassword string) error
    // 若 PasswordHash != "" → error("已设置密码，请使用修改密码")；否则 GeneratePasswordHash + UpdateById
```
**暴露状态**：`UserResponse` 增加 `HasPassword bool`（`ConvertToUserResponse` 里 `HasPassword: user.PasswordHash != ""`），同步 `MyProfile` TS 类型加 `hasPassword`。这样 `GET /api/user/profile` 一次返回即可驱动前端切换。

**UserController 新增**：`POST /api/user/set-initial-password`（`userAuth` 组），body `{ newPassword }` → `SetInitialPassword`。区别于现有 `PUT /api/user/password`（`ChangePassword` 需旧密码）。

**前端 `SecurityPanel.vue`** 按 `profile.hasPassword` 切换：
- `false`：渲染"设置密码"卡片（无当前密码字段），调 `setInitialPassword`，成功后刷新 profile。
- `true`：现有"修改密码"表单不变。
- 需把 `profile` 作为 prop 传入 `SecurityPanel`（`AccountPage.vue` 当前未传，需补 `:profile="profile"` + `@updated`）。

**副作用**：设密码成功后，解绑保护自动解除（`PasswordHash != ""` 使阻止条件不再命中），无需改解绑逻辑。

## 功能三：个人中心独立登录入口

### 现状（硬依赖 OIDC session）
- `/account` 未登录时（`getMyProfile()` 401）显示"您尚未登录 / 请先通过您使用的应用完成登录"，**无登录入口**（`AccountPage.vue:94-104`）。
- 登录为何必须有 client_id/session_id：
  - `InitSession` 第一步 `GetApplicationByClientID(req.ClientID)`，无效即拒。
  - `Login`/`LoginByCode` 第一步 `GetSession(req.SessionID)`，无 session 即 400，且 `SessionID` 是 `binding:"required"`。
  - `GetClientConfig` 经 `resolveClientConfigClientID`，client_id 与 session_id 两者全空即报错。
  - **关键**：`completeOIDCLogin` 里唯一必需 session 的是 OIDC Token 生成；而**个人中心 Cookie 签发 `issueUserSessionCookie` 不依赖 client/session**。→ 拆出无 client 登录路径完全可行。

### 是否已有"IAM 自身内置 client"
**没有**。`Application` 模型无 `IsSystem/IsBuiltin/IsDefault` 标志位；安装流程 `CreateInitialData` 只播种部门/角色/权限/管理员，不建默认 Application；全库无 first-party/default-client 概念。

### 落地选项

**选项 A：配置默认/内置 client 引导登录**
- 安装或迁移种一条 Application（固定 `client_id="mliev-console"`，redirect 指向 `/auth/#/account`）。
- 前端未登录态提供"去登录"按钮，用 `POST /api/oidc/init-session` 起 session 再走标准登录 UI，成功后 `completeOIDCLogin` 签发 Cookie 回跳 `/account`。
- 风险：console client 需在 consent 环节做"first-party 跳过授权确认"（当前无此概念，需新增标志位或固定 client_id 白名单），否则用户会看到对自己的授权页。

**选项 B（推荐）：新增不依赖外部 client 的自服务登录路径**
- 后端 `POST /api/user/self-login`（**public 组**，非 AuthMiddleware）：body `{ account, password }` 或验证码版：
  - 复用 `UserService.ValidateUserForLogin`（`user_service.go:551`）/ `GetVerifiedUserForCodeLogin`（`:622`）+ `VerifyCode`。
  - **不创建 OIDC session、不生成 OIDC Token**，仅调 `issueUserSessionCookie(ctx, user, rememberMe)` 签发个人中心 Cookie。
  - captcha 用 `ValidateForScene("login")`。
- 前端新增独立登录视图（如 `/account/login` + `AccountLoginPage.vue`），可裁剪复用 `OIDCAuthPage.vue` 的表单但去掉 session/client 依赖。
- **推荐 B**：后端复用度极高（两个现成 service + `issueUserSessionCookie`），与"个人中心靠 user_access_token Cookie、与 OIDC 解耦"的现有设计一致，不触碰 OIDC 授权链路。

## 汇总：需新增/修改清单

| 功能 | 后端 | 前端 |
|---|---|---|
| 一 邮箱/手机改绑 | UserService+`ChangeMyEmail/ChangeMyPhone`；UserController+3 接口（发码/改邮箱/改手机，`userAuth` 组）；DTO 3 个 | `ProfilePanel.vue` 改可编辑 + `api/user.ts` 3 方法 |
